# Performance Record整理GAS 日本語仕様

実行コードの正本は [`sheet_scripts/performance_record.gs`](../sheet_scripts/performance_record.gs) です。以前は同じコード全文をこの文書にも複製していましたが、更新漏れを防ぐため、ここでは運用仕様だけを記載します。

## 対象シート

- メイン: `Performance Record`
- 履歴: `履歴`
- ヘッダー: 3行目
- データ開始: 4行目
- 整理対象: A〜G列
- 並べ替え対象: 4行目から有効な最終行までの行全体

## 列

| 列 | 内容 |
|---|---|
| A | アーティスト名 |
| B | 曲名 |
| C | カテゴリ・備考 |
| D | 日付を文頭に含むリンク表示 |
| E | 出典元情報 |
| F | 掲載チェック |
| G | 最新更新日 |

## 重複整理

A列とB列をNFKC、大文字小文字、全角空白、連続空白を正規化し、同じキーを同一楽曲として扱います。

残す1行は次の順で決定します。

1. カテゴリ: `歌ってみた > 歌枠 > ショート > その他`
2. 同カテゴリ: D列文頭の `YYYYMMDD` が新しい行
3. 同日: G列の更新日が新しい行
4. すべて同じ: 上にある行

下位カテゴリは日付が新しくても上位カテゴリを置き換えません。残さない行はすべて `履歴` シートへ移します。

## E列・F列の継承

- 残す行のE列が空なら、履歴へ移す行のうち優先度が高い行から最初の非空値をリンク情報ごと継承
- 残す行のE列に値がある場合は上書きしない
- 同一楽曲のいずれかのF列が有効なら、残す行のF列も `TRUE`
- F列の明示的な `FALSE` は空欄とは扱わない

## 新規行の掲載チェック

A列またはB列を含む新規入力・貼り付けでA/Bが揃い、F列が空の場合、編集トリガーがF列へ `TRUE` を設定します。複数行やA:G全体の貼り付けにも対応します。既存行で意図的に空欄・`FALSE`としている掲載状態を、C〜F列だけの編集や整理処理から勝手に変更しません。

## 整理後の並べ替え

`Performance Record` の有効行全体を次の複合条件で並べ替えます。

1. B列（曲名）昇順
2. A列（アーティスト名）昇順
3. D列降順

罫線を含む既存の行範囲内だけを対象とし、ヘッダー行は移動しません。

## 実行方法

スプレッドシートを開き、メニュー `歌唱DB整理` から次を選びます。

- `DRY RUN（削除せず判定だけ）`
- `重複整理を実行`

DRY RUNでは履歴移動、E/F継承、並べ替えを実際には書き込みません。
